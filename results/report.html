It is not the GPU

A record crosses six stages between file byte and pixel: decompression, parsing, an in-memory representation, a thread boundary, an encode step, a draw. Each was individually reasonable and none profiled as the bottleneck — the cost was at the boundaries between them, where every stage handed the next a record in a shape that stage had to rebuild. A profiler charges that work to the stage doing the rebuilding, not to the boundary that forced it, so no measurement of a single layer points at it and no owner of a single layer can remove it.

The WebAssembly row is why that distinction decides the outcome: inflation alone gets 2.5–3× faster, but a query also fetches bytes and walks an index, so the multiplier reaches the user as a few percent. A stage optimized alone is bounded by the stages around it. The ones that compound are the ones that change what crosses a boundary — the columnar layout, the arena, and the zero-copy transport those two make possible.

Machine load

This is a shared workstation and these runs were taken while other jobs were on it. Any row whose load is above 4.0 is not comparable to one measured on an idle box. Contamination lands per cell, not per run, so a run whose average looks fine can still hold one ruined row — which is why the load is recorded either side of every cell rather than once per sitting.

The builds are measured back to back within each case, so a load spike tends to land on all four columns at once. That makes the ratios considerably more durable than the absolute milliseconds, and the ratios are what these tables are for.

What is and is not being compared

  • Cumulative, not isolated. Three years separate v2.4.0 from HEAD and almost none of it is the renderer. The 4.3.0 column isolates this release; the 2.4.0 column tells a reader of the paper what the intervening period bought them.
  • Same corpus as the paper. Reads were simulated with the same pbsim and wgsim invocations over the same 250 kb hg19 chr22 slice the 2023 methods describe.
  • Not the paper's own figures. Those plot a 10 kb region on 2023 hardware; this bench uses 19 kb on one 2026 workstation. v2.4.0 is re-measured here rather than quoted, so both columns come off the same machine on the same day.
  • One machine, one locus, one workload family. Alignment pileups only.
