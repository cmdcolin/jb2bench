# BGZF worker pool, on vs off, end to end in jbrowse

Generated by `scripts/bgzfpool/endtoend.ts` — edit the script, not this file.

Paired pan latency over 5 non-overlapping 19 kb windows on `chr22_mask`, 7 reps per track alternated ABBA, ratio taken per pair rather than between aggregates. Speedup above 1.0 means the pool is faster.

Two things invalidate a row and neither shows up in the ratio. **Foreign cores** above 0.5 means something else was using the machine. **Blob workers** is how many `blob:` worker targets each arm spawned: 4/0 is the pool engaged in builds/pool and off in builds/nopool, and anything else means the two arms were not different — `getSharedWorkerPool()` returns undefined wherever a Worker cannot be created and every read then quietly inflates in process, with no error and nothing failing.

What the pool can reach is measured separately by `scripts/bgzfpool/standalone.ts`, which runs the same query over the same windows with nothing above it. That is the ceiling this table is read against; `scripts/paperfigs/bgzfpool.R` draws the two together.
